# Google Play billing configuration

`BillingService` is the only Flutter boundary that knows about the Play Billing
plugins. The Rust planner verifies the signed Play `originalJson` before it
accepts Custom, Discord Nitro, or YouTube Shorts plans.

## Release keys

Configure these values in the trusted Android release build environment. They
are embedded into the Rust library at compile time; do not commit key material
or signing private keys.

- `ZUMI_PLAY_RSA_PUBLIC_KEY_PEM`: the Play Console license public key. PEM and
  base64 encoded DER are accepted.
- `ZUMI_LOYALTY_RSA_PUBLIC_KEY_PEM`: public key for the service that signs
  Zumi loyalty entitlement tokens. PEM and base64 encoded DER are accepted.

With no Play public key, Rust rejects Pro plans with
`E_PRO_SUBSCRIPTION_REQUIRED`. A loyalty token is optional; without one, Rust
reports zero accumulated months and a 2% next-month rate. No client clock or
unsigned renewal timestamp is used.

## Signed loyalty token

The optional `loyaltyToken` value is JSON for `LoyaltyReceipt`, including its
raw RSA signature as an integer array. Its signature covers the stable payload
generated by `rust/src/domain/licensing.rs::signed_payload`. The receipt's
purchase token and start time must match the Google-signed Play receipt before
Rust calculates consecutive calendar months.

Google's client purchase signature establishes the purchase data it signed;
it does not provide renewal history. A trusted issuer must supply the signed
loyalty token for accumulated months above the initial purchase to be shown.
